## Recommended missing-tool installation

Python can be provisioned for this project without a system-wide installer:

```powershell
uv python install 3.12
```

For the web shell:

```powershell
winget install --id OpenJS.NodeJS.LTS --exact
```

For Android/Flutter development, install Android Studio and a JDK, then install Flutter from the official stable channel. These are machine-level prerequisites and should be approved/managed by the workstation owner:

```powershell
winget install --id Google.AndroidStudio --exact
winget install --id EclipseAdoptium.Temurin.17.JDK --exact
git clone https://github.com/flutter/flutter.git --branch stable "$env:USERPROFILE\develop\flutter"
```

Add Flutter's `bin` directory to the user PATH, run `flutter doctor`, and accept only the Android SDK licenses required by the local Android setup.

## Bootstrap

From the repository root (the path contains a space, so keep it quoted when scripting):

```powershell
Copy-Item .env.example .env
.\scripts\bootstrap.ps1
```

The bootstrap script verifies prerequisites, creates `.env` if absent, and runs the backend dependency sync. Dependencies are pinned in `services/api/pyproject.toml` and the generated `services/api/uv.lock`.

The checked-in `apps/web/package-lock.json` is verified with `npm ci`, and `apps/mobile/pubspec.lock` is generated by `flutter pub get`. Keep both lockfiles committed when dependencies change.

The mobile Drift source is generated from `apps/mobile/lib/data/local_database.dart`:

```powershell
Push-Location apps/mobile
flutter pub get
dart run build_runner build
flutter analyze
flutter test
Pop-Location
```

## Local services and API

```powershell
.\scripts\dev.ps1
```

This starts PostgreSQL and MinIO through Compose and runs the API at `http://localhost:8000`.

Useful checks:

```powershell
Invoke-RestMethod http://localhost:8000/health
Invoke-RestMethod http://localhost:8000/ready
```

The readiness endpoint requires PostgreSQL to be reachable. The health endpoint only checks that the process is alive.

## Verification

```powershell
.\scripts\test.ps1
```

The script runs backend Ruff, mypy, pytest, and Alembic checks, then web lint/typecheck/build and Flutter format/analyze/test/debug-APK checks. PostgreSQL integration tests use the dedicated `fleet_test` database created by Docker Compose on a fresh local volume. `scripts/check-environment.ps1` prints the expected local toolchain versions before running the suite.

## Authentication configuration

Authentication settings use the `FLEET_` prefix. The important Phase 2
settings are:

```text
FLEET_PHONE_DEFAULT_REGION=IN       # optional; only for non-E.164 input
FLEET_OTP_PROVIDER=unavailable      # production must use a real provider
FLEET_ENABLE_DEVELOPMENT_OTP=false
FLEET_OTP_TTL_SECONDS=300
FLEET_OTP_MAX_ATTEMPTS=5
FLEET_OTP_RESEND_COOLDOWN_SECONDS=60
FLEET_JWT_SIGNING_KEY=<secret of at least 32 characters>
FLEET_JWT_ISSUER=fleet-manager-api
FLEET_JWT_AUDIENCE=fleet-manager-client
```

For local integration tests, inject a fake provider through test dependency
overrides. For manual non-production development, the in-memory development
provider requires both `FLEET_ENVIRONMENT=development`,
`FLEET_OTP_PROVIDER=development`, and
`FLEET_ENABLE_DEVELOPMENT_OTP=true`; it must never be enabled in production.
The default unavailable provider intentionally returns a service-unavailable
response instead of pretending to deliver an OTP.

The web shell uses `NEXT_PUBLIC_API_BASE_URL` when set and otherwise calls
`http://localhost:8000`. Run it from `apps/web` with `npm run dev`. The Phase 3
owner shell and Phase 5 supervisor verification shell keep tokens in memory
only, so refreshing the page intentionally returns to phone authentication. A
development OTP provider and signing key must be configured in the API
environment for a manual end-to-end login. Supervisor accounts must also have
an admin-created `SupervisorSiteAccess` grant before site data is visible.

## Migration workflow

Run from `services/api` after PostgreSQL is available:

```powershell
uv run --project . alembic upgrade head
uv run --project . alembic upgrade head --sql
```

Phase 1 adds `0002_core_domain`, which creates the domain tables, tenant
foreign keys, enums, checks, indexes, event idempotency constraint, and
assignment overlap constraints. Phase 2 adds `0003_authentication`, which
creates OTP challenge state and server-side authentication sessions. Run the online round trip against the test
database with:

```powershell
uv run --project . alembic upgrade head
uv run --project . alembic downgrade base
uv run --project . alembic upgrade head
```

Alembic uses the checked-in local URL by default and honors
`FLEET_DATABASE_URL` or `FLEET_TEST_DATABASE_URL` when an explicit database
is required. The test suite always requires a database name containing
`test`.

Phase 4 adds `0004_evidence_objects`. Phase 5 adds no migration; it reads the
existing event, verification, emergency, assignment, and evidence tables. Set
`FLEET_OBJECT_STORAGE_PROVIDER=s3` with the local MinIO credentials when
running evidence-upload flows; leave it `unavailable` when object storage is
not configured.
